# RinKuzu Source-of-Truth Registry

Status: canonical architecture registry, audited 2026-08-25.

This document is normative for runtime ownership. A collection may be durable without being authoritative. `authority` means the state that decides business behavior. `fact/ledger` means immutable or append-only business facts. `projection` means rebuildable state and must never override its fact/ledger source.

## Entitlement replay invariant

`entitlementgrants` and `entitlementadjustments` are the only business facts that determine the entitlement interval. `entitlementaccounts` is a replay projection and must satisfy:

1. `currentStartAt`, `currentEndAt`, `perpetual` equal a deterministic replay of ordered grants + adjustments.
2. `projectionChecksum` equals the checksum of that replay.
3. A `billingorders.fulfillmentStatus = fulfilled` paid order has exactly one source grant, unless the order is explicitly non-entitling by domain rule.
4. Every billing-sourced entitlement grant resolves to an existing paid/overpaid billing order for the same user.
5. `users.subscription` and `subscriptions` must not be read or written by canonical runtime after cutover. They remain migration input only until production reconciliation is approved and complete.

## Credit replay invariant

`creditledgers` is the authority. `creditwallets.balance` is a projection and must equal the sum of canonical ledger deltas for the wallet/user. Every unlock debit and admin/review reward must have one idempotent ledger source reference.

## Quiz/progress invariant

Completed attempt facts are immutable history. Resume/current progress may be mutable, but summaries must be rebuildable from canonical attempt/progress facts. A historical attempt may retain a quiz/question snapshot to preserve what the user saw; that snapshot must never replace `quizzes` as the current published quiz source.

## Web ↔ AI API boundary

Web owns identity, commerce, published quizzes, attempts/progress outside adaptive learning, community, credits and access control. AI API owns AI-generated drafts, adaptive pipeline/learning state, Ask Rin, dynamic LLM/OCR configuration, physical provider usage and AI document-processing artifacts. Web authenticates the end user and forwards a verified internal identity context; AI API must not create a second user/profile authority.

AI Mongo runtime database is explicitly `adaptive_learning` in `api/shared/mongo_store.py`; the database path embedded in `MONGODB_URI` is not the runtime database selector. Any future change must introduce one canonical database-name setting and a migration, rather than silently honoring two selectors.

## Canonical route naming

Canonical first-party HTTP paths must not encode implementation generations. External immutable provider protocol versions are exempt. Billing uses `/api/billing/*` and entitlement queries use `/api/entitlements/*`. A cutover wave must update every caller and remove superseded runtime handlers in the same release; no alias or silent fallback is permitted.

## Migration-only sources

The following are explicitly non-authoritative migration inputs until removed after approved production reconciliation:

- `users.subscription`
- `subscriptions`
- `questionprogresses.isBookmarked` when present
- any legacy premium storage namespace referenced only by migration tooling
- legacy collection archives retained outside runtime only when the approved retention policy requires them
